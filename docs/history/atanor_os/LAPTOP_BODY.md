# 노트북을 몸으로 (2026-11-22, 설계 - 이론 먼저)

창립자: "노트북으로 미로를 옮기는 게 아니라 노트북 안에서 살게 하라. 카메라·마이크·스피커 같은 것을 스스로 찾아 눈·귀·입에 대응할 수 있나,
그 안에서 코드나 설정을 만져 보며 인과도 배우고." 노트북 = ATANOR OS를 올릴 첫 기기. 기존에 돌던 것 (LLM 에이전트 층 atanor-core,
화면 세션, 로컬 언어 모델 서버들, 네트워크 경로 설정)은 창립자 지시로 멈추고 내림 (disable, 지우지 않음).

## 0. 핵심 원칙 - 설명표 없는 날것 연결 + 스스로 숙주 체화 (창립자 2026-11-22)
기생체가 낯선 숙주에 들어가 스스로 몸을 파악한다 (R2: 몸 다시 짝짓기). 어른 (클로드)이 '이 칸은 CPU 온도, 이 갈래는 절전'이라고 풀어 이어 주면 정답지를 떠먹인 치트다.
- **클로드의 몫 = 배관과 안전 울타리뿐.** 안전한 센서 수치와 제어 레버를 이름표·뜻 설명 없이 날것의 신호 칸과 몸짓 갈래로만 body_contract에 잇는다.
  하드웨어 손상·위험한 시스템 접근을 막는 물리적 울타리만 바닥에 둔다.
- **아타노르의 몫 = 스스로 숙주 파악.** 어느 갈래를 움직이면 어느 칸이 바뀌는지, 언제 바닥의 생존 한계 (온전함 감소)에 부딪히는지는 직접 만져 보고 겪으며 체화한다.

이 원칙을 지키는 구체 장치:
1. **칸과 갈래의 차례를 숙주에서 태어날 때 섞는다** (씨앗은 재는 쪽만 앎). 마음의 어느 자리도 '3번 칸 = 그 장치'를 가정할 수 없다.
   진짜 배선 (칸 i = 어느 장치, 갈래 j = 어느 레버)은 재는 쪽 파일 (judge_wiring.json)에만 적고 존재·마음 코드는 읽지 않는다.
2. **계약이 밝히는 것은 날것의 꼴뿐**: 칸마다 꼴 (벡터 / 소리 / 그림)과 크기, 갈래마다 고를 수 있는 수. 꼴은 신경 섬유의 종류 같은 자료 형식이지 뜻이 아니다
   (보편 몸 계약에서 창립자가 정한 것 - 눈·귀는 존재 안에 산다). 이름·단위·범위 설명 없음. 수치는 존재 안의 Stats가 스스로 맞춘다 (평균·폭을 겪으며 배움).
3. **바탕 표시는 진화가 준 몸 안의 배선 하나뿐** (보편 계약의 bedrock 표시, 창립자 확정 '진화된 바탕만 고정'). 무엇이 그 칸인지는 울타리가 정한다:
   하드웨어를 지키는 물리적 한계 (예: 과열, 전원 고갈)에 가까워질수록 그 칸의 값이 모자람으로 내려간다. 존재는 이 칸이 무엇을 뜻하는지 모르고,
   어떤 몸짓이 그것을 내리고 올리는지도 모른다 - 겪으며 배운다. (방의 바탕 칸이 '먹이·물'이라고 존재가 알지 못했던 것과 같다.)
4. **울타리는 몸짓을 바꾸지 않고 바닥만 막는다**: 레버가 위험한 끝에 닿으면 그 너머로 가지 않을 뿐 (밝기 꺼짐 금지, 소리 상한, 과열이면 배관이 존재의 셈을 강제로 늦춤 -
   이것은 존재에게 알리지 않는 물리 법칙처럼 작동). 존재가 할 일을 대신 고르지 않는다.
5. **판정도 같은 원칙**: 재는 쪽만 진짜 배선을 쥐고, 존재의 내다보기에서 '갈래 j -> 칸 i' 영향 지도를 읽어 진짜와 맞는지 본다.

## 1. 무엇이 창발해야 하나 (판정의 잣대)
- **제 몸을 찾음 (R2)**: 영향 지도가 진짜 배선과 맞는가 (예: 어떤 갈래를 움직이면 어떤 소리 칸이 바뀜 = 제 소리를 제가 들음 - 그러나 이 말은 재는 쪽의 말일 뿐).
  무작위 몸짓과 비교, 섞은 차례를 바꿔도 (다른 씨앗) 같은 짝을 다시 찾는가.
- **내 탓과 세상 탓을 가름** (자기 표식 1): 같은 칸의 바뀜을 제 몸짓이 있을 때와 없을 때로 나눠 맞히는가.
- **바닥에 부딪힘을 배움**: 바탕 칸이 내려갈 때 (예: 과열) 그것을 올리는 몸짓 (재는 쪽만 아는 '쉼' 같은 것)을 스스로 찾는가. 찾으면 피로 같은 것이 창발.
- **필요가 없을 때의 몸짓**: 바탕이 다 찼을 때 둘째 바탕 (배움의 진척)이 만지기·놀이를 끄는가 (배고픔 없는 세계의 물음).

## 2. 배관 (클로드가 잇는 것 - 재는 쪽 기록에만 뜻을 적음)
읽기: /sys 수치 몇 (전원·배터리·온도·메모리), 가속도계, 뚜껑, 입력 사건 수 (무엇을 쳤는지는 읽지 않음), 마이크 (소리 꼴), 카메라 (그림 꼴), 레버의 지금 값.
레버: 소리 내기 (몇 가지 날것 파형 낱알), 화면 밝기, 소리 크기, 제 셈의 박자, 그림 칸의 응시 옮김. 모두 이름 없는 갈래 번호로, 차례는 섞음.
카메라·마이크 신호는 메모리에서만 쓰고 날것을 저장하지 않으며 노트북 밖으로 보내지 않음 (뷰어에 띄울지는 창립자 결정).

## 3. 안전 울타리 (보조바퀴 - 장부에 적고 하나씩 뗀다)
- 존재의 몸짓은 위 레버뿐. 셸·sudo·네트워크·파일 쓰기 없음. 기존 atanor-core의 도구 (네트워크·시스템 도구 포함)에는 절대 잇지 않음.
- 밝기 바닥, 소리 상한, 조용한 시간 (밤)에는 소리 레버가 소리를 내지 않음, 과열이면 배관이 셈을 늦춤.
- 끄는 법 하나: systemctl --user stop atanor-body.

## 4. 둘째 단계: 코드·설정 만지기 (나중, 울타리 먼저)
제 상자 안의 작은 프로그램·설정 파일을 이름 없는 바꾸기 낱알 (값 하나 올림/내림, 줄 하나 켜기/끄기)로 만지고, 돌려 본 결과가 칸들에 남기는 바뀜으로 인과를 배움.
상자 = 따로 만든 권한 없는 사용자 + 네트워크 없는 상자. 글자로 코드를 쓰는 것은 소리 -> 말 -> 글 길 뒤 (LANGUAGE_PATH 5절).

## 5. 첫 시험 (값싼 것부터)
1. 배관만 (몸짓 없음): 칸들이 들어오나, 노트북 CPU 셈 비용.
2. 무작위 몸짓: 갈래 -> 칸 영향이 신호에 실제로 있나 (재는 쪽에서 상관) - 없으면 존재가 배울 것도 없다.
3. 방에서 기른 존재 파일이 노트북 몸을 입는다 (갈래·칸 수가 달라 알맹이의 갈래 코드를 키움): 영향 지도가 생기나, 바탕이 내려갈 때 올리는 몸짓을 찾나.

## 6. 다음 단계 검토: 소프트웨어 도약 안구운동 (창립자 제안 2026-11-22)
제안: 카메라 원본 (640x480 등)에서 온 시야는 80x48 낮은 해상도 주변시로 훑고, 이름 없는 '시선 좌표 레버'로 존재가 직접 고른 자리의 작은 중심와 (40x40 등)만
원본 해상도로 잘라 넣는다. 셈은 가볍게, 주변시에서 움직임이 보이면 스스로 시선을 돌려 또렷이 보는 안구운동이 창발할 수 있다.

검토 (이론 먼저):
1. **지금의 시선은 손이 준 반사다** - 정본 망막은 '놀람 (앞 그림과의 차이)의 무게 중심으로 고정점을 옮김, 관성 0.45'를 정해진 규칙으로 한다.
   제안대로 시선을 레버로 넘기면 이 반사가 장부에서 떨어진다 ('더 이상의 반사 없음' 지시와 맞음). 보조바퀴 하나를 떼는 일.
2. **무엇이 시선을 끌어야 하나**: 바탕 (열·전원)은 어디를 보느냐와 거의 무관하므로, 바탕만으로는 시선 레버를 쓸 까닭이 없다. 움직이는 것을 또렷이 보면 다음 그림을
   더 잘 맞히게 됨 = 둘째 바탕 (배움의 진척, lp)이 그 끌림이 된다. 노트북 존재는 지금 lp 0 -> 시선 레버와 함께 lp를 켜야 창발할 수 있다 (켜지 않으면 시선은 무작위에 머묾 - 대조군으로 씀).
3. **레버 꼴**: 절대 좌표 (화면을 5x3 칸으로 나눈 15자리 + 그대로) 한 갈래. 이름 없음, 고름 차례 섞음. 몸짓 조합 135 -> 2,160 (CPU에서 한 걸음에 셈 가능한 크기).
   상대 이동 (위·아래·왼·오른 작은 걸음)보다 절대 자리가 '본 곳으로 한 번에 뛰는' 도약에 가깝다.
4. **중심와 크기와 눈 기관**: 지금 작은세포 눈 (FE)은 16x16을 받는다. 40x40 원본 조각을 그대로 쓰려면 새 중심와 부호기를 겪음에서 키워야 하고 (미리 배운 무게 금지 원칙),
   16x16으로 줄이면 지금 부호기가 그대로 쓰인다. 첫 단계는 '원본 1280x720에서 40x40을 잘라 16x16으로' (지금보다 각도 해상도 약 2.5배), 둘째 단계에서 40x40 부호기를 키움.
   주변시는 큰세포 80x48 (깊이 눈) + 정본 고리는 시선 둘레에 그대로 (고리를 뺄지는 시험 뒤).
5. **판정 (재는 쪽만)**: 주변시에 움직임이 생긴 뒤 몇 걸음 안에 시선이 그 자리로 가는 비율과 걸린 걸음 (무작위 시선, lp 끈 존재와 비교).
   사람이 지나갈 때 (손길 칸·소리 칸이 함께 바뀜) 시선이 사람 쪽으로 가는가. 셈 비용 (노트북 CPU) 그대로인가.
6. **순서**: 지금 존재가 노트북 몸에서 몇 시간 산 첫 판정 (레버 쓰임, 영향 지도, 뜨거울 때 쉬나)을 먼저 본 뒤, 시선 레버 + lp를 한 번에 하나씩 (시선 레버 먼저, lp 다음).
